# 面试防守与自测

## 1. 三层追问自测（写完简历立刻自测，过不了就别写上简历）

1. 第一层「你做了什么」——事实层，能说清你的动作与产出物
2. 第二层「为什么这么选而不是另一种」——决策层，能给出对比与取舍（如 ReAct vs Plan-Execute、microVM vs 容器）
3. 第三层「重做一次会改进什么」——反思层，有明确改进点与教训

第三层答不出 = 项目还没沉淀成经验判断，写上去风险大。切勿编造没参与过的项目凑数，追问细节一眼辨真假。

## 2. 高频追问与考察点

| 追问 | 面试官在确认什么 |
|---|---|
| 你定义了哪些工具？边界怎么划的？ | 工具层抽象与接口设计能力 |
| 模型怎么知道该调用哪个工具？ | 决策逻辑（ReAct / Plan-Execute / 路由） |
| 工具调用失败怎么办？ | 工程鲁棒性与容错机制 |
| 怎么保证内容合规 / 安全？ | 安全约束与权限审计意识 |
| 为什么选这个范式，不选另一个？ | 技术决策链而不是跟风 |
| 上下文超长怎么裁剪？ | Memory 与 Context 管理 |
| 工具返回异常 / 格式不匹配怎么处理？ | Schema 校验与降级 |
| 你的评估方法本身有什么局限？ | 评测专业度（区分度、评测一致性） |
| 这个数字是怎么测的？基线是什么？ | 数字真实性 |
| 如果让你重做，会改哪里？ | 反思深度 |

## 3. 失败兜底四层拆解（答「调用失败怎么兜底」用这个结构）

- 调用层：超时、参数错误、权限不足 → 重试（带退避）、降级工具、幂等键防重复执行
- 推理层：幻觉、循环、误调用 → 最大步数限制、循环检测、门控路由兜底、强制澄清用户
- 模型层：输出不稳定、格式漂移 → Schema 校验、结构化输出、二次校验 / Reflection
- 消费层：用户不采纳、误用 → 人工升级通道、可解释展示（Trace）、操作审计与回滚

## 4. 常被问的口径题

- MCP 与 Function Calling 的区别：Function Calling 是模型能力层——模型在生成中按声明的 Schema 发起一次工具调用，解决「模型怎么调用工具」；MCP 是协议与生态层——工具/资源的标准化描述、发现、传输与多客户端复用，解决「工具怎么被标准化接入、一次开发多处复用」。
- Demo 项目能不能写：能，条件是做的不是参数配置而是架构决策（范式取舍、失败处理、评估设计）。课程/开源项目与实习项目说服力等价，核心是技术决策含量。
- 没数字怎么办：用小规模真实测量（测试集、压测、估算注明口径），体现数据意识比数字大小重要。

## 5. 口述框架

30 秒自我介绍：身份定位（方向 + 层级）→ 一个最能打的项目（角色 + 一个关键决策 + 一个指标）→ 与目标岗位的匹配点。

60 秒项目概述：场景与约束（10s）→ 架构与你负责的层（15s）→ 1-2 个关键决策及取舍（20s）→ 指标与项目边界（15s）。

## 6. 作品集 / 项目储备（经历不够时的补素材路径）

递进三件套：手写 Agent loop（吃透主循环）→ 带 Human-in-the-loop 的工作流（Interrupt/Resume、审批）→ 自研 MCP Server（Schema、权限、审计）。
「够 infra」的项目形态：权限模型 + 行为回归 + Trace 断言 + CI 重放。README 放 Trace 截图与 eval 分数，边界（原型 / 无生产数据）写清。
